## Which Drupal versions are supported?

Next.js for Drupal works requires Drupal 9.3+ and Drupal 10.

## Which Next.js versions are supported?

Next.js for Drupal supports both Next.js 14 and Next.js 15. This includes support for both the App Router and the Pages Router.

## Does it work without authentication?

Yes. Authentication is only required for previewing unpublished entities and revisions.

You can use Next.js for Drupal for pulling public JSON:API data and building static pages without authentication.

## Can I use the client with React Native?

Yes. Since 2.0 the core client (`NextDrupal`, `NextDrupalPages`, `NextDrupalBase`) has no runtime dependency on Next.js — it is plain `fetch` and `qs`. Methods like `getResource`, `getResourceCollection`, `translatePath`, `getMenu` and `getView` work in any JavaScript runtime. Only the draft mode helpers (`next-drupal/draft`) and the `useMenu` hook (`next-drupal/navigation`) require a Next.js application.

## Can I run Drupal and Next.js with Docker?

Yes. Keep the two applications in separate containers: Drupal in a PHP container (ddev, docker4drupal or a custom image) and the Next.js app in a Node container pointing `NEXT_PUBLIC_DRUPAL_BASE_URL` at the Drupal service. The [Quick start](/tutorials/quick-start) covers a ddev-based Drupal setup, and any Node image works for the frontend (`node:20` with `npm run build && npm run start`).

## Where can I try the authentication flow?

The hosted demo at [demo.next-drupal.org](https://demo.next-drupal.org) has authentication enabled — sign in with the username `example` and the password `example`.

## Does logging into the Next.js site log me into Drupal too?

No. The two applications keep separate sessions: authenticating on the Next.js side stores an OAuth access token for the frontend and never sets a Drupal session cookie. Signing into the Drupal backend (for editing) is a separate step. Sharing one login across both would require a dedicated single sign-on setup, which is outside what next-drupal provides.

## Error: Failed to fetch JSON:API index

The Next.js server could not reach your Drupal backend. Check, in order:

1. **The URL must be reachable from the Next.js server, not just your browser.** Inside Docker or ddev, `localhost` refers to the container itself — use the service name or the ddev hostname.
2. **Include the subdirectory when Drupal is installed in one** (e.g. `http://localhost:8080/drupal/web`). The client preserves the base URL path for subdirectory installs.
3. **Prefer `http://` for local https setups** (ddev, self-signed certificates) unless the Node process trusts the certificate.

## How do I get the URL or alias from a link field?

Link fields serialize as URIs (`entity:node/42`, `https://…`). To resolve them to aliases, install [jsonapi_extras](https://www.drupal.org/project/jsonapi_extras) and set the **URL** enhancer on the link field, or use the [core patch adding a computed URL](https://www.drupal.org/project/drupal/issues/3066751).
